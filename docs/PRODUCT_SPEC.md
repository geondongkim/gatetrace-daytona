# GateTrace 제품 기획서

> 이 문서는 GateTrace의 제품 범위와 구현 경계를 정하는 단일 기준 문서입니다. UI, API, 데모, 발표 자료는 이 문서와 충돌하지 않아야 합니다.

## 1. 한 문장 정의

GateTrace는 논문 작성과 연구 과정에 사용할 데이터를 제한된 검증 명세로 검사하고, 격리 실행 결과와 판정 근거를 함께 남기는 연구 데이터 검증 게이트입니다.

영문 표현:

> GateTrace is an evidence-first validation gate for data used in research and paper development.

## 2. 문제

연구자는 데이터를 분석이나 학습에 넣기 전에 품질을 확인하지만, 다음 정보가 분리되기 쉽습니다.

- 어떤 연구 목표와 입력을 검증했는가
- 어떤 검사 규칙을 적용했는가
- 어느 실행 환경에서 검사했는가
- 왜 승인하거나 격리했는가

결과만 남으면 오염 데이터를 잘못 채택하거나 유효한 데이터를 근거 없이 버릴 수 있고, 공동 연구자가 같은 판정을 다시 검토하기 어렵습니다.

## 3. 대상 사용자와 사용 시점

주 사용자는 연구자, 데이터 과학자, ML 엔지니어입니다. 논문 작성과 실험 과정에서 다음 시점에 사용합니다.

- 외부·공동연구 데이터를 분석 파이프라인에 넣기 전
- 학습 데이터셋을 모델 학습에 사용하기 전
- 데이터 정제 또는 증강 결과를 채택하기 전
- 결과 재현을 위해 입력과 판정 근거를 보존할 때

## 4. 제품 범위와 현재 실증 범위

제품 방향은 연구 데이터 전반입니다. 센서 데이터 전용 제품으로 설명하지 않습니다.

현재 해커톤 MVP의 실증 범위는 표 형식 센서 CSV 두 개입니다.

- 정상 샘플: 네 게이트 통과, `APPROVED`
- 오염 샘플: 결측률·시간 순서·누수 의심 열 실패, `QUARANTINED`

현재 구현된 네 게이트:

1. 필수 열 / Required columns
2. 결측률 / Missing-rate threshold
3. 시간 순서 / Time order
4. 누수 의심 열 / Forbidden leakage columns

문서·이미지·비정형 데이터 검증은 제품 확장 방향이며 현재 구현 완료 기능으로 주장하지 않습니다.

## 5. 핵심 사용자 흐름

```text
연구 목표와 검증할 데이터 선택
        ↓
Nosana 제한 검증 명세 생성
        ↓
Daytona 호스트 소유 검증기 격리 실행
        ↓
결정적 APPROVED / QUARANTINED 판정
        ↓
구조화 근거와 한영 설명 보존
```

## 6. 스폰서 통합 역할

### Nosana

- 자연어 연구 목표를 허용된 네 게이트의 제한 명세로 변환합니다.
- 판정 결과를 한국어와 영어로 설명합니다.
- 명세 또는 설명 생성에 실패하면 fallback 상태를 명시합니다.
- Daytona가 만든 결정적 판정을 변경할 수 없습니다.

### Daytona

- 호스트가 소유한 검증기와 입력 데이터를 격리된 샌드박스에서 실행합니다.
- 구조화된 게이트 결과를 반환합니다.
- 실행 후 샌드박스를 삭제합니다.
- Daytona 실패 시 `ERROR`를 반환하며 로컬 실행으로 우회하지 않습니다.

## 7. 결과 계약

모든 판정은 번역 문장이 아니라 구조화 값과 함께 반환합니다.

```json
{
  "id": "time_order",
  "status": "PASS",
  "message_key": "gate.time_order.pass",
  "evidence": {
    "ordered_rows": 12,
    "total_rows": 12
  }
}
```

실행 결과에는 최소한 다음 추적 정보를 포함합니다.

- 요청 ID
- Daytona 샌드박스 ID
- Nosana 모델 ID 또는 fallback 상태
- 실행 시간
- 게이트별 상태와 증거
- 한국어·영어 요약

## 8. UX 원칙

- 기본 언어는 `한영`, 선택값은 `localStorage`에 저장합니다.
- `한국어`, `English`, `한영` 모드에서 문구가 누락되지 않아야 합니다.
- 데스크톱 1440×900과 1366×768의 주요 상태에서 문서 수준 가로·세로 스크롤이 없어야 합니다.
- 주요 상태는 시작, 실행 중, `APPROVED`, `QUARANTINED`입니다.
- 결과 화면은 판정, 게이트 근거, 샌드박스 ID, 모델 ID, 실행 시간을 한 화면에서 확인할 수 있어야 합니다.
- 센서 데이터는 데모 예시로 표시하고 제품 범위처럼 표현하지 않습니다.

## 9. 확인된 증거와 주장 경계

2026-09-19에 다음을 확인했습니다.

- 실제 Nosana `qwen/qwen3.8-27b` 명세와 한영 요약 생성
- 실제 Daytona 정상·오염 샌드박스 실행과 삭제
- 정상 `APPROVED`, 오염 `QUARANTINED`
- 로컬과 Vercel 반복 라이브 실행의 전체 경로 약 20.8~41.1초
- Vercel 프로덕션 https://gatetrace-daytona.vercel.app 의 루트, 헬스, 정상 샘플 E2E

위 수치는 단일 해커톤 실행의 관측값이며 성능 보장으로 사용하지 않습니다. 현재 데모 데이터는 결정론적 fixture이며 실제 연구 데이터의 성능·정확도 개선을 증명하지 않습니다.

## 10. 확장 로드맵

우선순위가 높은 다음 단계는 증거가 남는 데이터 증강입니다.

- Nosana가 허용 변환과 제약을 명세화
- Daytona가 호스트 소유 변환 코드만 격리 실행
- 생성 이력, 원본 구간, 파라미터, 시드 보존
- 증강 후 동일 게이트를 다시 적용하고 통과분만 채택

문서 입력은 문서 전용 검증기를 설계한 뒤 확장합니다. 두 항목 모두 현재 MVP에서는 계획입니다.

## 11. 제외 범위

- DNSimple 연동
- 파일 업로드와 사용자 로그인
- 외부 공개 배포
- 생성형 모델이 직접 판정을 변경하는 기능
- 증강 실행과 문서 검증의 완료 주장
- 사용자 확인 전 제출 폼 업로드
