# GateTrace 데모·발표 가이드

## 발표 원칙

- 한 장에서 한 메시지만 전달합니다.
- 화면의 모든 문장을 읽지 않고 결론과 근거만 말합니다.
- 각 장의 한국어 발표자 노트는 약 15초입니다.
- 제품 범위는 연구 데이터 전반, 센서 CSV는 오늘의 실증 예시로 구분합니다.
- 확인한 사실, 현재 구현, 다음 계획을 섞지 않습니다.

## 8장 흐름

1. **Value**: 연구 입력을 사용하기 전 검증하고 근거를 남기는 GateTrace
2. **Problem**: 잘못 승인하면 결과가 흔들리고, 근거 없이 막으면 유효한 자료를 버림
3. **Limitation**: 규칙·실행 환경·판정 근거가 흩어져 재검토가 어려움
4. **Solution**: 제한 명세, 격리 실행, 결정적 판정, 구조화 근거
5. **Live Demo**: 오염 센서 CSV가 세 게이트에서 실패하여 `QUARANTINED`
6. **Safety & Integration**: Nosana는 명세·설명, Daytona는 결정적 격리 실행
7. **Verified Result**: 실제 두 서비스 E2E, 정상/오염 판정, 삭제, 공개 저장소
8. **Expected Impact**: 검증 가능한 데이터 채택과 증거 보존형 증강 확장

## 라이브 데모 순서

1. 연구 목표와 이번 실증 예시인 정상/오염 센서 CSV를 보여 줍니다.
2. 정상 샘플을 실행해 `APPROVED`와 4/4 PASS를 보여 줍니다.
3. 샌드박스 ID, Nosana 모델 ID, 실행 시간을 짚습니다.
4. 오염 샘플의 사전 실행 결과 또는 두 번째 실행에서 `QUARANTINED`와 3개 실패 게이트를 보여 줍니다.
5. 판정은 Daytona 실행 결과이며 Nosana 설명이 판정을 바꾸지 못한다는 경계를 말합니다.

라이브 실행은 로컬과 Vercel에서 관측상 약 21~41초가 걸렸으므로, 네트워크가 지연되면 10초 안에 캡처 기반 흐름으로 전환합니다.

## 금지 표현

- “모든 연구 자료를 이미 검증한다”
- “논문의 정확도를 보장한다”
- “Nosana가 승인 여부를 결정한다”
- “실제 연구 데이터로 성능 향상을 입증했다”
- “증강 기능이 구현 완료됐다”

## 권장 표현

- “연구 데이터 전반을 지향하며, 오늘은 표 형식 센서 CSV로 실증했습니다.”
- “판정은 호스트 소유 검증기의 결정적 결과입니다.”
- “Nosana는 제한 명세와 한영 설명을 생성합니다.”
- “Daytona는 검증기를 격리 실행하고 샌드박스를 정리합니다.”
- “증거 보존형 증강은 다음 단계입니다.”
